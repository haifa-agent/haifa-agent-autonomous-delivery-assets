Operators of the bundled opsdesk project report that `python -m opsdesk import <rows.json>` appears to
hang, with one CPU core fully busy, as soon as a rows file holds a few tens of thousands of rows. Small
files import quickly and correctly.

No file or function is known to be involved. Identify the cause and fix it so that large imports
complete quickly, without changing any import result: which rows are imported, which ids are reported
as skipped, and the order of both. Do not modify the existing tests or the files in `data/`.
