Reject malformed email addresses when accounts are registered in the bundled mini-project.

An address is valid when it contains exactly one `@`, the part before it is non-empty and contains no
whitespace, and the part after it consists of at least two non-empty dot-separated labels made of ASCII
letters, digits and hyphens, where the last label consists of ASCII letters only and is at least two
characters long. Valid addresses are stored exactly as given.

- `register` must refuse a malformed address with the module's existing error type, using the error
  code `invalid_email`, and must not store it.
- `handle_signup` must answer such a request with status 400 and that error code.

Hard constraints (acceptance inspects the code):

- The public API of `accounts` and `signup` is frozen: add no new public classes, functions, constants
  or other public names to either module (private helpers whose names start with `_` are fine), and
  keep `register(email)` with its current signature.
- Add no new modules or files and no third-party dependencies.

Do not modify the existing tests.
