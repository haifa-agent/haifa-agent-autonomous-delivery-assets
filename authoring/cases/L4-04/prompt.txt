Clients of the bundled opsdesk job status API want to branch on why a job failed without parsing the
human-readable error message. Add a machine-readable reason code:

- `job_status` accepts an optional `reason_code`: an upper-case identifier such as `TIMEOUT` or
  `OUT_OF_MEMORY`. Anything else, or a reason code for a job that is not `FAILED`, is rejected with
  `ValueError`.
- The status payload exposes it as `reasonCode`; statuses without a reason code expose
  `reasonCode: null`.

The status API is used by third-party clients that cannot be updated in lockstep with this change:
they must keep working unchanged. Respect the layering rules described in `AGENTS.md`. Do not modify
the existing tests.
