Tasks in the bundled opsdesk project need a priority.

- A task has an integer `priority` from 1 (highest) to 5; the default is 3.
- Clients may send `priority` when they create a task through `TaskApi`. Every task payload returned
  by the API (create, read and list) contains it, and `TaskApi.schema()` declares it as an `integer`
  field.
- Priorities must survive a restart of the file-backed task store. Task files written before this
  change contain no priority and must still load, with the default priority.
- Creating a task with a priority outside 1..5 is rejected with `ValueError`, and nothing is stored.

Respect the layering rules described in `AGENTS.md`. Do not modify the existing tests or the files in
`data/`.
